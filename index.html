How it works

Welcome to Text-o-Matic

Text-o-Matic turns a list of phone numbers into a tap-through queue of personalized text messages. Write your message once, add names or other details with merge fields, and Text-o-Matic prepares each message for you. No more copying and pasting the same message over and over again.

  1. Add your list by pasting phone numbers or uploading a CSV or Excel workbook.
  2. Choose the phone column, the name shown for each recipient, merge fields, and ignored columns.
  3. Write a message using fields like {{First Name}}.
  4. Review missing data and customize fallback messages when needed.
  5. Send with SMS or WhatsApp on this device, or transfer the prepared list and messaging-app choice directly to another device.
Private by design — and you can verify it.

Your contacts, uploaded file contents, phone numbers, merge-field values, and message text are processed locally in your browser. Text-o-Matic does not send that information to me or to Cloudflare Web Analytics.

Don't take my word for it: once Text-o-Matic says Offline ready, disconnect from the internet and keep using it; inspect the open-source code; or watch your browser's network traffic while you use the app.

Privacy

How Text-o-Matic handles your data

Your contact and message data stays on your devices. Text-o-Matic processes uploaded file contents, phone numbers, names, merge fields, and message content entirely in your browser. That information is not uploaded to Text-o-Matic and is not sent to Cloudflare Web Analytics.

You can verify this yourself. Once the app reports Offline ready, it can keep preparing lists and messages with your internet connection turned off. You can also inspect its network traffic while you work or read the source code on GitHub.

Device Transfer does not upload your list. Text-o-Matic encodes the transfer data directly into one or more QR codes. The code contains the data needed to rebuild the prepared list on the other device; it does not point to a copy of your contacts stored on a server. See exactly how this works.

Opening a message hands it to the messaging service you selected. SMS links are passed to your device's texting app. WhatsApp links include the recipient phone number and prepared message so WhatsApp can open the conversation with the text filled in. From that point, WhatsApp's own service and privacy practices apply.

Keep Device Transfer codes private. Because the prepared contact and message data is in the QR code itself, treat the code like the list itself and do not share or save it.

Basic usage analytics. Text-o-Matic uses Cloudflare Web Analytics so we can tell whether the site is being used and how it performs. It provides aggregate information such as visits, page views, and performance metrics. It does not receive your imported contacts, merge-field values, or message text, and Cloudflare Web Analytics does not use cookies or local storage for analytics.

Local browser storage. Text-o-Matic uses browser storage such as IndexedDB and local storage for app functions including preferences, usage counters, incomplete Device Transfers, and other local state. This information remains in your browser unless you clear it.

Verify it yourself

Inspect Text-o-Matic's network traffic

You can use your browser's built-in developer tools to see every network request Text-o-Matic makes while you use it.

  1. Open Text-o-Matic, then open your browser's developer tools. In Chrome, Edge, and Firefox, F12 or Ctrl+Shift+I usually opens them.
  2. Select the Network tab and reload the page so you can see the requests made when the app starts.
  3. Paste or upload a test list, map its columns, and build a message while the Network tab remains open.
  4. You will see ordinary requests needed to load the site, its libraries, and anonymous analytics while online. What you should not see is Text-o-Matic transmitting your uploaded file contents, contact list, phone numbers, merge-field values, or message text.
  5. For an additional check, wait until the footer says Offline ready, disconnect from the internet, and continue using the app.
One important boundary: when you choose to open a prepared message, Text-o-Matic hands the recipient and message to the messaging app or service you selected. Network activity from that app or service is outside Text-o-Matic.

View the source code on GitHub if you'd also like to inspect how the app works.

Device Transfer

How can a QR code work without uploading my list?

A QR code is just machine-readable data. It does not inherently mean “internet” or “website.” Text-o-Matic puts the information needed for the transfer directly into the code itself.

There is no online copy of your contact list for the QR code to retrieve. When the other device scans the code, Text-o-Matic reads the encoded data and reconstructs the prepared list locally on that device.

The code does include the Text-o-Matic web address so your camera can open the app. The private transfer data is placed after the # in that address (the URL fragment). Browsers do not send URL fragments to the web server when requesting a page, so the encoded contact/message payload is not part of the normal request to Text-o-Matic.

If the receiving device has not already cached Text-o-Matic, it may need internet access to load the app itself. That is separate from transferring your list: the contact and message data remains encoded in the QR code rather than being fetched from a server.

Easy way to think about it: the QR code is the envelope carrying the data, not a claim ticket for data stored somewhere online.

Keep the code private. Because the transfer information is actually in the QR code, someone who can scan the code may be able to read the transfer. Treat it like the contact list itself.
